# LAPACK explicit-inverse baseline and strict paired audit

Version 1.1.0 adds a production explicit-inverse baseline based on the
LAPACK routines `xGETRF+xGETRI`.

## Environment used on Picasso

- Python 3.11.4
- NumPy 1.24.3
- SciPy 1.10.1
- one BLAS thread per Slurm array task

The SciPy wrappers were explicitly checked to dispatch

- `SGETRF+SGETRI` for binary32;
- `DGETRF+DGETRI` for binary64.

## Balanced sample

The baseline uses exactly the deterministic balanced stochastic sample from
the original large-scale campaign:

- 64 stochastic cells;
- 13 dimensions:
  `8, 11, 16, 23, 32, 45, 64, 91, 128, 181, 256, 362, 512`;
- 2000 selected matrices per cell/dimension block;
- 832 blocks;
- 1,664,000 matrices per precision;
- 3,328,000 matrix/precision LAPACK records.

The selection is not replicas 0--1999.  It is the deterministic hash-ranked
selection generated by the original `analyze_recovered.py` logic.

## LAPACK completion

Binary32:

- attempts: 1,664,000
- successes: 1,655,277
- `SGETRF INFO>0` failures: 8,723
- failure rate: 0.52421875%

Binary64:

- attempts: 1,664,000
- successes: 1,664,000
- failures: 0

Of the 8,723 binary32 failures, 8,663 (99.31%) occur in the
`random_conditioned` family.  The failures are concentrated in
prescribed-condition cells with `kappa_2 >= 1e8`, beyond the reciprocal
binary32 roundoff scale.

## Strict six-method comparison

Let `S5` denote common success of the five Castillo variants and let `S6`
add LAPACK success.

Counts are

- binary32: |S5| = 1,635,974; |S6| = 1,629,883;
- binary64: |S5| = |S6| = 1,663,999.

For the final residual comparison an additional common finite-metric
condition is imposed for all six methods.  The resulting sample contains

- 1,629,883 binary32 matrices;
- 1,663,993 binary64 matrices.

The six removed binary64 records are successful Castillo computations for
which the two-norm residual diagnostic is not finite.

## Table-2-style result

Entries are medians over the 832 blocks of the within-block quantiles of
`r_R/u`.

| method | binary32 q50 | binary32 q95 | binary64 q50 | binary64 q95 |
|---|---:|---:|---:|---:|
| R0_C0 | 2.618558 | 5.921340 | 4.868489 | 14.494002 |
| R0_C1 | 1.079431 | 1.598915 | 1.428014 | 2.096688 |
| R0_C2 | 1.079431 | 1.573634 | 1.449088 | 2.142702 |
| R1_C1 | 1.341902 | 1.825482 | 1.640220 | 2.227354 |
| R2_C2 | 1.283325 | 1.802039 | 1.651936 | 2.179891 |
| LAPACK xGETRF+xGETRI | 1.331457 | 2.366415 | 2.114235 | 3.602090 |

The four magnitude-based Castillo variants are competitive with LAPACK and
have smaller blockwise q95 values in both precisions.  The result does not
imply uniform matrix-by-matrix superiority.

## Successful Castillo records with unavailable r_R,2

A scan of the complete recovered Castillo population found

- 146,540,408 successful inverse records;
- 40 successful records without a valid finite `r_R,2`;
- fraction 2.73e-7 of all successful records.

All 40 are binary64 `R2_C2` records:

- 35 `scaled_adversarial`, n=256;
- 5 `random_conditioned`, n=724.

Residual summaries therefore use successful records for which the requested
norm evaluation is finite.

## Repository material

`slurm/lapack_baseline/` contains the Picasso launch and archive-recovery
scripts.
